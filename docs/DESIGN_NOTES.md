# 設計筆記

這個 repo 的主張不是「做了一個準的模型」，而是**一套 pipeline 服務很多棟建築，
以及一套判斷「這個準確率能不能信」的流程**。以下是幾個非顯而易見的設計決定。

## 為什麼主軸是公版化

一棟建築做得準不難，難的是第二棟、第五十棟不必重來一次。
所以規則閾值、選樣條件、模型設定全部外部化到 `config/pipeline.json`，
`src/run_quality.py` 對 465 棟跑同一套邏輯——**新增建築只改設定檔，不改程式碼**。

## 零膨脹：這個資料集最重要的性質

冰機關機時讀數就是 0，資料集裡有建築零值佔比達 77–80%。
任何以「整體分布」估計的統計量都會被這些代表正常關機的 0 拖垮。
同一個根因在 P1 踩了三次（平坦段規則、突刺尺度、上限分位數），
三條規則最後全部改在**非零子集**上估計。

寫新規則前先問一句：這個統計量遇到大量 0 會怎樣？

## 時序洩漏有兩種，第二種不會被靜態檢查抓到

第一種是用未來的負荷算過去的特徵，靠 `shift`／`closed='left'` 可防，
並以**行為檢測**釘死（竄改序列尾端後，前段特徵須逐格不變）。

第二種是**用實際的未來天氣當特徵**。生產環境只拿得到氣象預報，
離線用實測值等於假設預報零誤差——程式上完全合法，任何靜態檢查都抓不到。
本專案把它做成明碼開關 `weather_mode`，兩種模式都跑，差距就是預報的價值。

## 宣稱紀律

宣稱門檻寫死在 `src/analyze_p3.py`／`analyze_p4.py`，避免事後看 p 值挑形容詞：
`p<0.05` 可宣稱／`0.05–0.10` 有跡象／`>=0.10` 落在雜訊帶內；
另加「差距須大於 2 倍標準誤」的雜訊帶門檻，`n<3` 一律標不判定
（Welch 對 `n<3` 回 `nan`，而 `nan < 0.10` 是 `False`，會靜默落到錯誤的結論）。

負面結果照樣報。本專案最重要的一條結論就是負面的：
**主結論取決於 45 個評估視窗中的 2 個**，因為視窗層級的門檻沒有事前宣告，
所以立場採「不可宣稱」，而不是排除掉那兩個視窗再宣稱。

## 環境陷阱

**lightgbm 與 torch 的 OpenMP 衝突**（macOS／Apple Silicon）：兩者各帶一份 OpenMP runtime，
任一方先載入、另一方後使用都會 SIGSEGV，**沒有 Python 例外**，看起來像程式被殺掉。
`KMP_DUPLICATE_LIB_OK` 無效。唯一雙向穩定的解是在載入任何 OpenMP 使用者之前
把執行緒數壓到 1（見 `src/models.py` 頂端與 `tests/conftest.py`）。

**Git LFS 指標檔**：資料集用 Git LFS，直接抓 `raw.githubusercontent` 只會得到 133 bytes 的
指標檔——副檔名是 `.csv`、HTTP 回 200、檔案存在，但內容不是資料。
`src/fetch_data.sh` 走 LFS batch API 取真檔並以 SHA256 對帳。

## 靜默失敗的五個實例（都由測試抓到）

1. `pandas.interpolate(limit=n)` 的語意是「每段最多填 n 格」，
   所以 12 小時的長缺口會被填掉前 5 格——正是該規則要防的事。
2. 標的含 NaN → loss 變 `nan` → `nan < best` 恆為 False → val loss 停在 `inf`
   → 上層把整個架構跳過且不報錯，症狀是「結果表裡就是沒有那幾列」。
3. `trained_at` 用牆鐘時間，歷史回放算出負間隔 → 冷卻期永遠成立 → 重訓永遠不觸發。
4. ingestion 契約層只驗負值未驗上限，`1e9` 直接通過。
   修法不是用資料自身估上限（零膨脹下會讓每個非零讀數變違規），而是改用設備銘牌，
   且**沒有銘牌就不判**。
5. skill 同時定義在 SQL view 與 Python 查詢兩處。植入「view 的分子分母寫反」，全部測試照樣綠燈，
   因為測試讀的是 Python 那份。修法是 view 成為唯一定義、Python 只讀。**同一個指標只能有一個定義處。**

## 誠實邊界

- 全部是**公開資料上的方法論驗證**，不是生產環境或任何真實場域的導入成果。
- 服務層是可運行原型：無認證授權、無 rate limiting、無備份還原、無監控告警。
- 端到端「模型推論 → 落庫 → 儀表板」尚未接上 P3 的實際模型，
  目前以合成序列驗證資料流與冪等。
- 規則閾值以物理理由選定，但**未經領域工程師覆核**。
