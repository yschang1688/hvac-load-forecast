# P13 補充 — 學校行事曆的來源（跑實驗 B2 之前寫）

擷取時間：2026-10-05 12:30–12:55（台北時間）。本檔在看到任何 P13 結果之前提交。

## 狀態：實驗 B2 暫緩（2026-10-05 裁定）

B2 的設計保留，不執行。理由：目標客戶以公營單位、政府機關、企業與工廠為主，學校類建築的需求少；補齊四所學校的行事曆再跑一次（約 110 分鐘）的收益低於成本。

**重新啟動的條件**：出現學校類的真實案場（那時用客戶提供的行事曆，不用推定的），或要對外宣稱「學校行事曆有增益」時。

這一輪留下來的結論不依賴 B2：不同用途的建築，日曆與特徵的定義不同。所以新案場上線時，先依用途分類，由分類決定預設的特徵與日曆，再依客戶的實際營運微調。見 `reports/P13_REPORT.md` 第五節。

## 為什麼補這一份

`P13_PLAN.md` 寫「BDG2 沒有學校身分，正確的行事曆拿不到」。這句說得太早。BDG2 的 `metadata.csv` 有每棟建築的經緯度和時區，可以定位到城市，再查當地大學 2016–17 學年的官方行事曆。

## 第三步：實驗 B2 的設計（寫死）

- 樣本：實驗 B 的 11 棟學校裡，site 對得到學校的那幾棟（Bull、Fox、Hog、Moose）。Bobcat、Eagle 沒有座標，不進 B2。
- 旗標 `site_break`：各 site 用自己學校的停課日。停課日＝「最後上課日的隔天」到「下學期開學日的前一天」，再加春假（或 Winter Break）整週。期末考期間另做一個旗標 `site_exam`，因為考期的建築使用和上課不同。
- 行事曆只用官方來源。**當年行事曆讀不到時的補法**：用同一所學校最近三個學年的行事曆，取「開學是 1 月第幾個星期幾、春假是 3 月第幾週」的規則，回推 2016–17 的日期，並在結果表上標「回推」。回推的 site 另外單獨報一次，不和官方日期的 site 混在一起下結論。
- Moose 有兩所候選學校：用卡爾頓的日期，另用渥太華大學的日期做一次敏感度分析（待查到渥太華大學行事曆）。
- 變體：`base`、`+generic_break`（實驗 B 的通用旗標）、`+site_break`、`+site_break+site_exam`。判定規則與實驗 B 相同。
- 主要比較：`+site_break` 對 `base`；次要比較：`+site_break` 對 `+generic_break`（對的日曆有沒有比通用日曆好）。

## 仍然存在的限制

- 評估期是 2017-01 到 2017-04。有了各校行事曆後，評估期內的停課日變多（1 月上半、2 月或 3 月的春假），但暑假仍在封存測試期，本輪不開封。
- site 對學校是推定。推定錯了，旗標就是錯的日曆。
- ASU 與 UMN 的日期補齊之前，B2 只能跑 Bull 與 Moose 兩個 site（各 2 棟），樣本很小。
