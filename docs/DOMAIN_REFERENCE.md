# 領域參考：商用 AI 冰水主機節能系統的輸入與功能

本專案用的是公開建築計量資料（BDG2），沒有真實案場的控制迴路。
以下整理一份公開的產業專文所描述的商用系統樣貌，用來對照**本專案做了什麼、沒做什麼**。
出處：智慧化居住空間產業聯盟（內政部建築研究所主辦、工研院執行），
〈台灣愛淨節能科技-「AccuSave AI™智慧空調節能軟體」結合AI優化空調系統的典範〉，
https://www.ils.org.tw/report/1398 （以下為摘述，非轉載）。

## 商用系統的三類輸入與三項功能（摘述）

輸入分三類：**環境變數**（溫濕度、室內外負載變化）、**設備狀況**（流量、壓差、溫度變化）、
**能源效率**（COP、EER）；另有氣象預報、室內人流、工作時程、設備使用習慣、外牆隔熱性能等。
功能有三：①檢視冰水主機組的操作合理性、②剖析操作策略的性能表現、③預測每日製冷負荷，
預測範圍為未來數小時到數天，並主動調節負載與循環水量。

## 對照本專案

| 商用系統 | 本專案 | 差距 |
|---|---|---|
| 功能③ 預測每日製冷負荷 | P3：day-ahead 24 步多步預測，三策略 × 四架構 | 顆粒為小時級；商用場景常為 15 分鐘級 |
| 功能① 操作合理性檢視 | P1：六條品質規則、三級判定 | 本專案只檢視**資料**合理性（零膨脹、突刺、卡死），無設備操作面 |
| 功能② 策略性能剖析 | P4：重訓 vs 從不重訓對照組；PSI 失效量測 | 無真實控制策略可剖析 |
| 輸入：氣象預報 | `weather_mode`：perfect_forecast（實測未來天氣＝零誤差上界）／lagged_only（無預報下界） | 沒有真實預報資料，只能夾出上下界 |
| 輸入：室內人流、工作時程、設備使用習慣 | **無**，只有日曆特徵當佔用率代理 | 這是概念漂移（使用行為改變）在本資料上難以由輸入分布偵測的一個原因 |
| 輸入：設備狀況（流量、壓差）、COP／EER | **無** | P5 的物理上限規則因此改為「有銘牌才判」——資料自身估上限在零膨脹下會失效 |
| 多廠牌、新舊機台加裝控制器取數 | P5：兩套廠牌方言 → canonical schema | 商用系統的異質性遠高於本專案模擬的兩種方言 |

## 一個立場

該專文把傳統控制稱為 rule-based、AI 控制稱為 learning-based。本專案的品質閘也是 rule，
但它管的是**資料可不可信**，learning 管的是**預測**——兩層不是取捨關係。
沒有前一層，後一層學到的可能是計量器卡死那 5,742 小時的常數。
